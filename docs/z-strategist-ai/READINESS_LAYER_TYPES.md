# Z-Strategist AI — Readiness Layer Types

**Posture:** Clarification doctrine · not operational scoring

## Three separate readiness types

Z-Strategist indicators must **not** be confused with each other:

| Layer | Question it answers | Example signal |
| ----- | ------------------- | -------------- |
| **Doctrine readiness** | Is vision, governance, and documentation sound? | ZILWA 2B listening kit = doctrine GREEN |
| **Technical readiness** | Do verify scripts, boundaries, and build posture hold? | `npm run verify:md` PASS |
| **Deployment readiness** | May this go public, accept users, or activate revenue? | Always **HOLD** until AMK gate |

## Critical rule

> **Doctrine readiness documents are not proof of operational readiness.**

A project may have:

- **GREEN** doctrine (strong framework, receipts, static exhibits)
- **AMBER** technical posture (report drift, open PRs, verify gaps)
- **RED** ecosystem posture (e.g. hub `z:traffic` rollup not fully GREEN)
- **HOLD** deployment authority (default)

## How indicators map

| Indicator | Primary layer |
| --------- | ------------- |
| Vision, Documentation | Doctrine |
| Technical, Security, Privacy | Technical + doctrine |
| Banking, Legal, Tax/VAT | Commercial / deployment planning |
| Deployment Risk, Revenue Activation Risk | Deployment |
| EDR | Cross-project (all layers) |
| Human Gate Status | Deployment authority |

## Operator discipline

Before answering:

- "Do we need a company yet?"
- "Do we need VAT review yet?"
- "Can this go public?"
- "Can this accept payments?"

Check **stage**, **revenue exposure**, and **Human Gate** on the project readiness card — not doctrine quality alone.
