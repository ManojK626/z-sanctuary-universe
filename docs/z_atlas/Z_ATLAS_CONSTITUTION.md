## Purpose

Z-Atlas is a **governed, evidence-based topology** for:

- **HUMAN NAVIGATION** — where a product, root, gate, or conflict actually lives
- **AI NAVIGATION** — what identity, path, and authority an agent must load before acting

Z-Atlas maps the organism. It does not command the organism.

---

## Lock doctrine

1. **Z-ATLAS MAPS THE ORGANISM. IT DOES NOT COMMAND THE ORGANISM.**
2. **IDENTITY PRECEDES ACTION.**
3. **PATH PRECEDES MUTATION.**
4. **CANONICAL AUTHORITY MUST BE PROVEN, NOT INFERRED.**
5. **SIMILAR NAME DOES NOT MEAN SAME PRODUCT.**
6. **A HUB REFERENCE DOES NOT MEAN SOURCE OWNERSHIP.**
7. **DISCOVERY DOES NOT AUTHORIZE INGESTION.**

10. **Z-ATLAS MUST REUSE EXISTING IDENTITY, HEALTH, PROVENANCE AND COMMUNICATION SYSTEMS RATHER THAN DUPLICATE THEM.**

## Architecture (required)

```text
EXISTING SYSTEM → EVIDENCE / STATE → Z-ATLAS TOPOLOGY → HUMAN / AI CONTEXT
```

Forbidden:

```text
Z-ATLAS → duplicate canonical engine → competing authority
```

Atlas consumes evidence. Atlas does not become a second registry, second health engine, second provenance store, or second command plane.

## Authority model

Every Atlas node that claims identity or path must carry, when known:

| Field | Meaning |
| --- | --- |
| `identityStatus` | Who/what this is, as proven |
| `authorityStatus` | Who may speak for it |
| `canonicality` | Whether this is the proven canonical instance |
| `ownership` | Who owns source vs who may only point |
| `environment` | Local / hub / external / archival as proven |
| `gateState` | Open, hold, blocked, missing |
| `healthState` | Overlay from existing observers — not invented GREEN |
| `evidenceFreshness` | CURRENT / AGING / STALE / UNKNOWN |

### Authority vocabulary

`CANONICAL` · `EXTERNAL_SOVEREIGN` · `REFERENCE_ONLY` · `HISTORICAL` · `ARCHIVAL` · `SUPERSEDED` · `UNRESOLVED` · `MISSING`

Do not silently map `UNRESOLVED` to `CANONICAL`.  
Do not silently map `UNKNOWN` to `GREEN`.

## Mapping law

- Similar name ≠ same product.
- A hub reference ≠ source ownership.
- Discovery ≠ ingestion authorization.
- A worktree ≠ the product root.
- A commercial family ≠ code merge.
- Health GREEN ≠ deployment authorized.
- Deployment HOLD ≠ product identity failure.

---

## Supervised learning rule

```text
OBSERVE → PROPOSE → STEWARD REVIEW → AUTHORIZED CHANGE
```

Never:

```text
OBSERVE → SELF-MODIFY
```

Learning may propose topology corrections. Stewardship promotes them. Atlas itself must not auto-register roots, auto-repair paths, auto-ingest products, or auto-upgrade UNKNOWN.
