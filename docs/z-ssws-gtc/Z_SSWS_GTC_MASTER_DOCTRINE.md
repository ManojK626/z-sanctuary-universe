# Z-SSWS-GTC — GitHub, Tooling & Cloudflare Command Spine

**Lane:** Z-SSWS-GTC Phase 0 (doctrine only)  
**Hub:** Z-Sanctuary Universe

## Tri-layer command spine

```text
Cursor   = builder workspace
GitHub   = vault / PR gate
Cloudflare = future edge / access posture
```

Purpose: organize commands, protocols, PR posture, CI results, Cloudflare future phases, and operator receipts **without** granting execution authority.

## Core laws

```text
command spine ≠ execution authority
GitHub status ≠ merge permission
Cursor plan ≠ approved work
Cloudflare posture ≠ production bind
tooling insight ≠ sacred approval
AI report ≠ operator decision
```

Inherited from builder spine (see [Z_OPERATIONAL_TECHNOLOGY_LAYERS.md](../Z_OPERATIONAL_TECHNOLOGY_LAYERS.md)):

```text
federation ≠ authority
topology ≠ ownership
observe → verify → suggest → human decides
readiness ≠ deploy
organization ≠ control
layered tools ≠ the soul
```

## What Z-SSWS-GTC does

| Area | Role |
| --- | --- |
| Command boundaries | Separates what each tool may surface vs execute |
| GitHub protocol | PR, checks, history, rollback trail — vault posture |
| Cursor protocol | Branches, diffs, interpretation — builder workspace |
| Cloudflare protocol | Future-phased edge and access research only |
| Advisory tracking | Open PR queue, CI failures, branch map, receipts (read-only) |
| Human gate | AMK decides merge, deploy, charters, sacred moves |

## What Z-SSWS-GTC must NOT do

- auto-merge, auto-deploy, or silent runtime expansion
- treat green CI as merge permission
- bind production on Cloudflare without charter
- expose NAS, raw RDP, or undeclared tunnels
- duplicate long doctrine from GitHub gate, Cloudflare precautions, or OTL
- become sole governance source over Hierarchy Chief or Turtle Mode
