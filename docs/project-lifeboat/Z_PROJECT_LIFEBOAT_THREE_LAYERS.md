## Identity shift

Until the Guiding Principle, Lifeboat was mainly **evaluating providers**.  
Now it also defines the **laws** by which every future provider will be judged.

That separation is what gives long-term durability.

---

## Layer 1 — Principles (Immutable)

These should outlive every technology:

| Principle | Meaning |
| --- | --- |
| Evidence-led | Dated sources over preference |
| Recovery-tested | Restore drills over “backup success” |
| Migration-aware | Steward Exit before lock-in |
| Steward-reviewed | Human gate on preservation decisions |
| **Framework outlives technologies** | The evaluation model must survive the tools it judges |

Permanent sentences:

1. *Every preservation decision shall be evidence-led, recovery-tested, migration-aware, and steward-reviewed.*  
2. *Every preservation framework shall outlive the technologies it evaluates.*

---

## Layer 2 — Framework (Long-lived)

Project Lifeboat itself — may evolve **slowly and deliberately**:

- Provider / ecosystem evaluation  
- Steward Exit Score  
- Appliance Stewardship Score  
- Cost models (including cost-through-time)  
- Recovery methodology  
- Preservation architecture  
- Evidence Board · charters · ceremonies  

Change only with steward review — not fashion.

---

## Layer 3 — Providers (Replaceable)

Today’s implementations — **expected to change**:

Backblaze B2 · Cloudflare R2 · Synology C2 · GitHub · future names  

Technologies come and go. Layers 1–2 remain.

## After Phase 0 core trio (B2 · R2 · C2)

Do **not** rush AWS · Azure · GCS · Hetzner · Storj · …

```text
3 ecosystems complete
        ↓
Framework review (Has the model become stable?)
        ↓
Adjust scoring if needed
        ↓
Only then expand research
```

If three very different ecosystems fit the same model, that is evidence the **framework** is sound.
