# Z-SEIF Constitution

**Gate:** `Z-SEIF-0`  
**Name:** Z-Sovereign Edge Intelligence Fabric  
**Short ID:** `Z-SEIF`  
**Posture:** PROJECT-SCALE · SPECIALIST CAPABILITY LANE · ARCHITECTURE ONLY  
**Runtime:** none. This document grants no Worker, Hook, Action, or deploy authority.

## North star

> PROJECTS REMAIN SOVEREIGN.  
> ATLAS KNOWS WHERE THEY ARE.  
> CURSOR BUILDS.  
> GITHUB CUSTODIES.  
> CLOUDFLARE OPERATES.  
> AI OBSERVES, EXPLAINS, AND PROPOSES.  
> THE STEWARD AUTHORIZES.

Companion locks (inherited, not rewritten):

- Identity precedes action. Path precedes mutation.
- Canonical authority must be proven. Similar name ≠ same product.
- Hub reference ≠ source ownership. Discovery ≠ ingestion.
- AI recommendation ≠ authorization. Cloud capability ≠ permission to use it.
- UNKNOWN never silently becomes GREEN. Silence ≠ health.
- Local/private data does not become cloud data by convenience.

Z-SEIF inherits [Universe Constitution](../governance/Z_SANCTUARY_UNIVERSE_CONSTITUTION_V1.md) by reference. It does not supersede it.

## Purpose

Create a **governed coordination fabric** across the multi-project ecosystem without collapsing sovereign products into one monolith.

Z-SEIF is the **platform-edge** layer: how Cursor (engineering execution), GitHub (source + custody + engineering evidence), and Cloudflare (operations) attach to existing Sanctuary intelligence.

It is **not** a new organism roof.

```text
Z-OTF  = how trust, evidence, comms, knowledge, and work compose inside the organism
Z-ATLAS = where things are, and what identity an actor must load
Z-SEIF = how Cursor / GitHub / Cloudflare edges attach without new engines
```

If a proposed Z-SEIF subsystem already exists, the required action is REUSE / EXTEND / INTEGRATE.

## What Z-SEIF is not

Z-SEIF is **not** a replacement for:

- Z-Atlas
- PID
- Z-CLDO
- Z-PACE
- provenance systems
- health / alert systems
- AI Tower
- Zuno / Zulu
- product-specific engines
- a universal database
- a universal autonomous super-agent

Z-SEIF coordinates existing and future capabilities.

## Additional doctrine

| Rule | Meaning |
| --- | --- |
| `LEAST_CAPABILITY_BINDING` | A future runtime receives only the storage, AI, queue, workflow, database, and secrets it needs |
| `MERGE ≠ PRODUCTION DEPLOYMENT` | A GitHub merge is custody, not production authority |
| `TEST PASS ≠ DEPLOY AUTHORITY` | Green tests are evidence, not a release grant |
| `AI APPROVAL ≠ STEWARD APPROVAL` | Specialists recommend; Steward authorizes |
| `EVENT ≠ AUTHORITY` | An event may observe, diagnose, HOLD, or request review — never silently mutate |
| `SOVEREIGN_PRODUCT ≠ Z-SANCTUARY SOURCE TREE` | A control plane may know a product without owning its source |

## Steward Control Plane (design only)

A future **Z-Steward Control Plane** may show topology, custody, deployment, health, alerts, cost, AI activity, gates, and receipts.

It must **not** become product source authority.

This phase does not build it.
