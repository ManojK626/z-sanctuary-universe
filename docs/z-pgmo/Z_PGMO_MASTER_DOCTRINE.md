# Z-PGMO — Projects Genius Management & Operator

**Lane:** Z-PGMO Phase 0 (doctrine only)  
**Hub:** Z-Sanctuary Universe (`Z_Sanctuary_Universe`)

## Purpose

Z-PGMO is a **read-only governance and improvement layer** that helps the ecosystem understand many cross-projects as living systems: identity, boundaries, phase, risks, and next safe steps — **without** becoming an execution authority.

> Projects Genius Management & Operator watches, maps, suggests, and receipts. It does not own, merge, deploy, or command.

## Core law

```text
management ≠ control
improvement ≠ permission
cross-project insight ≠ ownership
operator guidance ≠ autonomous execution
```

Golden operational chain (aligned with Turtle Mode):

```text
Observe → Verify → Suggest → Human decides
```

Readiness is not permission. Passing checks is not deploy approval.

## Reinforcement boundary (Phase 0.1)

When Z-PGMO links to **AMK-Goku Indicators** and **Z-Team AI**, these laws apply:

```text
indicator ≠ permission
AI team advice ≠ approval
management insight ≠ execution
dashboard visibility ≠ authority
```

Flow (advisory only):

```text
project state → indicator posture → Z-Team advisory routing → AMK human decision
```

## What Z-PGMO does

| Area | Role |
| --- | --- |
| Project identity | States each project’s purpose and home repo |
| Boundary map | Declares what belongs and what must not cross |
| Phase status | Labels doctrine, mock, runtime, deploy hold |
| Improvement radar | Suggests next safe upgrades (receipts only) |
| Cross-project links | Surfaces shared engines without merging them |
| Risk posture | Flags overlap, drift, unsafe expansion |
| Merge queue awareness | Respects Turtle Mode order; no reordering by AI |
| Indicator posture map | Connects project phase to AMK indicator signals (read-only) |
| Z-Team AI routing | Suggests which advisory role reviews a lane (no approval) |
| Receipts | Records recommendations; no silent edits |
| Human gate | AMK decides sacred moves |

## What Z-PGMO must NOT do

- auto-merge or auto-deploy
- hidden runtime, daemons, or background orchestration
- project takeover or “AI owns the roadmap” language
- rewriting all repos from one lane
- Cloudflare, NAS, RDP, or device control
- secrets write or provider calls
- flipping amber to green without receipts and human sign-off
- overriding or auto-editing AMK indicator JSON from PGMO
- treating Z-Team AI routing packets as merge or deploy approval

## Phase 0 scope

Phase 0 + **0.1** are **docs only**: master doctrine, boundary map, improvement radar, operator queue policy, green receipt, and AMK/Z-Team reinforcement links. No scripts, dashboard edits, registry JSON, or npm tasks unless a future chartered phase adds them with human approval.

## Operator authority

**AMK-Goku** remains final authority on merge, deploy, billing, legal copy, public launch, bulk user data, and all sacred moves per hub governance.
